01

What is Query Cost?

Query cost represents the amount of computational work associated with executing a database query. Database optimizers consider different execution strategies before choosing a plan.

QueryLens uses an educational cost model. It estimates how many rows survive each filter using table statistics, then charges every plan operator for the page reads and CPU work it performs.

Table Scan Reads every row of a table to find matching records.
Index Search Uses an index to seek directly to the matching range.
Selectivity The fraction of rows a predicate is expected to keep.
Join Combines records from two or more tables.
Temporary Structure Needed for sorting, grouping or distinct operations.
Cardinality The estimated number of rows flowing out of an operator.

FAQ

Frequently Asked Questions

Is QueryLens completely browser-based?

Yes. All parsing, execution and costing run in JavaScript inside your browser. Nothing is sent to a server.

Does QueryLens use a real database server?

No. It generates a demonstration dataset in browser memory each time the page loads. It requires no Node.js, SQLite or server.

What SQL is supported?

SELECT queries with WHERE, AND, OR, NOT, parentheses, IN, BETWEEN, LIKE, IS NULL, JOIN and LEFT JOIN, GROUP BY, HAVING, aggregates, DISTINCT, ORDER BY and LIMIT. Subqueries, UNION and window functions are not supported and will be rejected.

Is the cost score a real optimizer's cost?

No. It is an educational metric. The model estimates selectivity from static table statistics and charges operators for page reads and CPU work in the style of a real planner, but the numbers are not produced by an actual database engine.

Why do my row counts differ slightly from the examples?

The dataset is randomly regenerated on every page load, so exact counts vary between sessions. Estimates assume a uniform distribution, the same assumption a real planner makes when it has no histogram.

Does the CREATE INDEX suggestion actually create an index?

No. QueryLens has no DDL engine. The statement is advice to run against your own database; re-analysing here will not change the plan.

How are the quiz questions produced?

They come from a curated bank of solved DBMS questions, topped up by a generator that composes new questions from the live table statistics, so the pool never runs out. The quiz does not call an external AI service, because a browser-only site cannot hold an API key securely.

Are the competitive exam questions real past papers?

Not verbatim. Questions labelled with a GATE year paraphrase a concept reported from that paper; questions labelled "GATE-style Practice" are original. Verify any year label against the official GATE papers before citing it.

Where is analysis history stored?

In this browser's localStorage. It is never uploaded, and Clear History removes it.

Can I save my analysis as a PDF?

Yes. Choose Print / Save PDF from the Download menu, then select "Save as PDF" in your browser's print dialog.
