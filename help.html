QUICK START

Analyze your first query in 30 seconds

New here? Follow these five steps.

1. Open the analyser

Go to the Analyze page and scroll to Analyze your SQL query.

2. Pick a demo

Choose any query from the ⚡ Demo Queries dropdown. It loads and runs straight away.

3. Read the score

Look at the 1–100 score circle. Green (75+) is cheap, red (below 45) is expensive.

4. Check the advice

Scroll to Optimization Advisor and Suggested Rewrites to see how to improve the query.

5. Try your own

Edit the query, or upload a .sql file, and press Ctrl + Enter to compare.

STEP-BY-STEP GUIDE

Every feature, explained

A walkthrough of each part of QueryLens.

01

Enter or Upload SQL

Type a SELECT query into the editor, pick one from the Demo Queries dropdown, click Load Example to cycle through demos, or click 📂 Upload .sql to load your own file.

02

Analyze Query & Cost

Click Analyze Query, or press Ctrl + Enter. QueryLens parses the SQL, runs it against the in-browser dataset and calculates its estimated cost.

03

Check the Score

The score runs from 1 to 100, where higher is cheaper. Read it alongside the estimated cost, execution time and rows returned.

04

Read the Cardinality

Selectivity is the fraction of rows your filter keeps. Estimated Rows is how many survive. Index Used names the index column, or shows "none" when a full scan is needed.

05

Study the Execution Plan

Each line shows one operator with its estimated rows, its cost and its share of the total. The cost chart ranks the same operators so you can see where the work goes.

06

Apply the Advice

The Optimization Advisor explains what it found. Suggested Rewrites gives copy-ready SQL and CREATE INDEX statements to run on your own database.

07

View the Result Rows

The Query Result table shows up to 100 rows from your query. Empty values appear as NULL.

08

Verify with Tests

Click Run Tests to run built-in cases covering filters, joins, aggregates, subqueries, file splitting and invalid input. Each case checks a specific expected result.

09

Download a Report

Use the Download menu for a Text, Document, JSON or printable PDF report. It includes your query, the plan, the cost breakdown, the advice and sample rows.

10

Reuse Past Queries

Analysis History lists your ten most recent queries. Click any entry to load and re-run it. Click Clear History to remove them.

11

Take the Quiz

Open Quiz, choose how many questions you want and pick Easy, Medium or Hard. Each answer is marked straight away with an explanation.

12

Practise 50 GATE PYQs

Open Competitive Exam, search or filter by sections A–G, then select an option. The correct answer and a full solution appear after you choose. Use "Test SQL in Analyser" on SQL questions to run them.

13

Switch Day or Night

Use the sun and moon button at the top right. Your choice is remembered in this browser.

14

Share a Query Link

Add ?sql= followed by your query to the analyser address, e.g. index.html?sql=SELECT * FROM products. The query loads and runs automatically.

UPLOADING SQL FILES

How file upload works

Upload a .sql or .txt file with the 📂 Upload .sql button, or drag and drop it onto the editor.

📄 Several queries in one file

Separate queries with semicolons (;). QueryLens splits the file, runs the first SELECT and shows a dropdown so you can pick any other one.

⏭️ Non-SELECT lines are skipped

Statements such as CREATE TABLE, INSERT or UPDATE are skipped safely. The upload bar tells you how many were skipped.

💬 Comments are ignored

Both -- line comments and /* block comments */ are removed before the queries are analyzed.

📏 Limits

  • File types: .sql or .txt
  • Maximum size: 2 MB
  • Queries must use the demo tables (see below)

Example upload file

-- my_queries.sql
CREATE TABLE ignored (id INT);   -- skipped

SELECT category, COUNT(*) AS n
FROM products
GROUP BY category;

SELECT * FROM orders
WHERE status = 'Shipped'
LIMIT 20;

This file gives you 2 SELECT queries, with 1 statement skipped.

DATABASE REFERENCE

Tables you can query

QueryLens creates this demo database in your browser each time the page loads. Only these three tables exist.

👤 customers — 3,000 rows

  • id INTEGER
  • name TEXT — e.g. "Customer 12"
  • email TEXT
  • country TEXT — 8 values (India, USA, UK, Canada, Australia, Germany, Singapore, UAE)
  • city TEXT — 10 values (Chennai, Mumbai, Delhi, Bangalore, Hyderabad, Pune, New York, London, Toronto, Sydney)
  • created_at DATE (2025-01-01 to 2026-08-31)

Indexed: id, country, email

📦 products — 500 rows

  • id INTEGER
  • name TEXT — e.g. "Laptop 7"
  • category TEXT — 6 values (Electronics, Books, Clothing, Home, Sports, Beauty)
  • price REAL — 20 to 2,000

Indexed: id, category

🧾 orders — 25,000 rows

  • id INTEGER
  • customer_id INTEGER → customers.id
  • product_id INTEGER → products.id
  • order_date DATE
  • quantity INTEGER — 1 to 5
  • amount REAL — price × quantity
  • status TEXT — Delivered, Shipped, Processing, Cancelled

Indexed: id, customer_id, product_id, order_date, status

    READING THE RESULTS
    
What the score and metrics mean


    

      

        
75 – 100
Low cost

        
Close to the cheapest possible plan. Usually an index lookup with a small result.

      

      

        
45 – 74
Moderate

        
Some extra work, such as a sort, grouping or a scan of a medium-sized table.

      

      

        
1 – 44
High cost

        
Expensive operations, such as full scans of large tables, unindexed joins or big sorts. Check the advice.

      

    


    

      

        
MetricMeaning

        
          
Estimated CostAbstract "cost units" based on pages read and rows processed (similar to PostgreSQL's planner). Lower is better.

          
Execution TimeHow long the query actually took in your browser, in milliseconds. It varies from run to run.

          
Rows ReturnedHow many rows the query produced (the table shows up to 100).

          
Full ScansHow many times a whole table had to be read row by row.

          
Index SearchesHow many times an index was used to jump straight to matching rows.

          
Temporary StructuresExtra work areas needed for GROUP BY, ORDER BY or DISTINCT.

          
Estimated RowsHow many rows the planner predicts will pass the WHERE filter.

          
SelectivityThe percentage of rows the filter keeps. A small percentage means a selective filter.

          
Index UsedThe indexed column used for the lookup, or "none".

Please enter a SQL query.The editor is empty.Type a query or choose a demo.

Data modification … not allowed.The query contains INSERT, UPDATE, DELETE, DROP, etc.Remove those keywords. QueryLens is read-only.

          
Multiple SQL statements are not supported.More than one query is typed in the editor.Analyze one at a time, or upload them as a .sql file.

    OPTIMIZATION TIPS
    
Write cheaper SQL


    

      

        
1. Avoid SELECT *

        
List only the columns you need. Less data is read and sent, and covering indexes become possible.

      

      

        
2. Filter on indexed columns

        
Filtering on country uses an index; filtering on city scans the whole table.

      

      

        
3. Add a LIMIT

        
If you only need a few rows, say so. It also makes ORDER BY much cheaper.

      

      

        
4. Filter before grouping

        
Put row conditions in WHERE, not HAVING, so fewer rows reach GROUP BY.

      

      

        
5. Avoid leading wildcards

        
LIKE 'abc%' can use an index; LIKE '%abc' cannot.

      

      

        
6. Join on indexed keys

        
Join on id / customer_id / product_id. Unindexed joins turn into slow nested loops.

      

      

        
7. Use DISTINCT sparingly

        
Duplicates often come from a join that multiplies rows. Fixing the join is cheaper than removing duplicates afterwards.

      

      

        
8. Prefer JOIN over big IN lists

        
A JOIN lets the optimizer use indexes on both sides instead of building a long list of values.

      

    

  



  

  

    GLOSSARY
    
Key terms


    

      

        
TermDefinition

        
          
CardinalityThe number of rows in a table or in an intermediate result.

          
SelectivityThe fraction of rows a condition keeps. For col = value, roughly 1 ÷ (number of distinct values).

          
IndexA sorted structure (usually a B-tree) that lets the database find rows without reading the whole table.

          
Sequential (full) scanReading every row of a table, one page after another.

          
Index scanUsing an index to jump straight to the matching rows.

          
Hash joinBuilds a hash table on one input, then probes it with the other. Fast for equality joins.

          
Nested loop joinFor each row on one side, scan the other side. Slow on large unindexed tables.

          
Hash aggregateGroups rows using a hash table to compute COUNT, SUM, AVG, etc.

          
Execution planThe ordered list of operations the database will perform to answer a query.

          
PageA fixed-size block of rows read from disk. QueryLens assumes 50 rows per page.

          
Covering indexAn index that contains every column a query needs, so the table itself never has to be read.

          
Leftmost-prefix ruleA multi-column index can only be used if the query filters on its first column.

        FAQ
        
Frequently Asked Questions

      

    


    


      

        How do I upload a SQL file to estimate cost?
        

          Click 📂 Upload .sql in the SQL Input panel, or drag and drop a
          .sql / .txt file onto the editor. QueryLens reads the file,
          finds every SELECT query and analyzes the first one. If there are several,
          use the dropdown in the upload bar to switch between them.
        

      


      

        My file has CREATE TABLE / INSERT statements. Will it still work?
        

          Yes. Those statements are skipped and only the SELECT queries are analyzed.
          The upload bar shows how many statements were skipped.
        

      


      

        Can I use my own tables?
        

          Not yet. QueryLens runs against its built-in demo tables:
          customers, products and orders.
          Any other table name gives an "Unknown table" error.
        

      


      

        Is QueryLens completely browser-based?
        

          Yes. All parsing, execution and costing run in JavaScript inside
          your browser. Nothing is sent to a server, and it works offline once loaded.
        

      


      

        Does QueryLens use a real database server?
        

          No. It generates a demo dataset in browser memory every time the
          page loads. The values are random, so exact row counts and results
          change slightly after each refresh, while table sizes stay the same.
        

      


      

        What SQL statements are supported?
        

          SELECT queries with WHERE, AND, OR, NOT, parentheses, IN (including IN subqueries),
          BETWEEN, LIKE, IS NULL, comparison operators, INNER/LEFT JOIN, GROUP BY, HAVING,
          COUNT, SUM, AVG, MIN, MAX, DISTINCT, ORDER BY and LIMIT.
          See Supported SQL for the full list.
        

      


      

        What does the Query Score mean?
        

          Scores run from 1 to 100, where 100 is best. They reward index
          usage, selective filters and small result sets, and penalise full
          scans on large tables, unindexed joins and large sorts.
        

      


      

        Why is the execution time different every time?
        

          Execution time is measured live in your browser and depends on your
          computer, other open tabs and caching. Use the Estimated Cost to
          compare queries; it stays the same for the same query.
        

      


      

        How is Selectivity calculated?
        

          Selectivity is the fraction of rows expected to satisfy a WHERE
          condition. For an equality test on a column with V distinct values,
          selectivity is 1/V. AND conditions are multiplied together; QueryLens
          multiplies the result by the table size to predict surviving rows.
        

      


      

        Why does QueryLens recommend CREATE INDEX statements?
        

          When a query filters on an unindexed column, QueryLens detects the
          full scan and suggests an index that would turn it into a direct
          lookup. These are suggestions for your real database; QueryLens does not run them.
        

      


      

        Why does my query return 0 rows?
        

          Check spelling and values: countries, cities, categories and statuses
          must match the values in the Database Reference.
          Text comparisons ignore upper/lower case, but 'Bombay' won't match 'Mumbai'.
        

      


      

        Why does the result table show only 100 rows?
        

          To keep the page fast, the table shows the first 100 rows.
          "Rows Returned" still shows the full count.
        

      


      

        Where is my history stored? How do I delete it?
        

          History is saved in your browser's local storage on this device only.
          Click Clear History in the Analysis History panel to delete it.
        

      


      

        Can I print or save a PDF of my analysis?
        

          Yes. Choose Print / Save PDF from the Download menu, then select
          "Save as PDF" in your browser's print dialog.
        

      


      

        Does QueryLens work on mobile?
        

          Yes. Use the ☰ menu to navigate. A larger screen is easier for
          reading execution plans and wide result tables.
        

      


      

        The demo queries or upload don't seem to work. What should I do?
        

          Hard refresh with Ctrl + Shift + R. Then click
          Run Tests on the Analyze page — every test should pass.
          If not, press F12 and check the Console for red errors.
